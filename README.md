# RuLeaks.Следопыт

Веб-инструмент для HUMINT-расследований: поиск через API RuLeaks, досье, графы связей.
Архитектура и принятые решения — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Запуск (прототип)

```bash
npm install
cp config.example.ini config.ini   # необязательно: без файла — демо-режим по умолчанию
npm run dev
```

- Фронтенд: http://localhost:5173 (Vite проксирует `/trpc` на сервер)
- API: http://127.0.0.1:3001 (`[server] host/port` в `config.ini`)

Сервер работает на in-memory данных: после перезапуска (в том числе при сохранении файла в `tsx watch`)
досье, расследования и сессии сбрасываются к демо-набору. При `[bot-db] enabled = false` на странице входа есть кнопки,
которые имитируют подтверждение входа ботом:

| Профиль | Что проверить |
|---|---|
| **Следопыт** | активная подписка, владелец демо-досье и расследования |
| **Коллега** | безлимит; владелец публичного расследования и досье «Морозов»; редактор расследования о подрядчиках, читатель досье «Петров» |
| **Без подписки** | режим только для чтения |

## Конфигурация

`config.ini` в корне (шаблон с комментариями — [config.example.ini](config.example.ini), сам файл в `.gitignore`):

| Секция | Назначение |
|---|---|
| `[server]` | адрес, порт, секрет cookie, `dev-login` |
| `[project-db]` | БД сайта: пользователи, сессии, история поиска, досье, расследования (`enabled = false` — в памяти с демо-данными) |
| `[bot-db]` | БД Telegram-бота: пользователи, токены, подписки, только чтение (`enabled = false` — демо-учётки) |
| `[api]` | API-сервер dsstalker-api-gate (`enabled = false` — имитация с вымышленными данными) |

С `[bot-db] enabled = true` вход на странице входа — по Telegram ID пользователя бота (dev-вход, только на localhost),
подписка и токен API берутся из базы бота. С `[api] enabled = true` поиск идёт в реальный API-сервер.

Любой ключ можно переопределить переменной окружения `FT_<СЕКЦИЯ>_<КЛЮЧ>`,
например `FT_PROJECT_DB_PASSWORD`, `FT_SERVER_PORT`. При старте сервер пишет в лог сводку
подключений (без паролей) и предупреждает о неизвестных ключах.

## Имитация шлюза (dev)

- Поиск в Telegram по нику: ник с `multi` (например `@multi_user`) — несколько Telegram ID и выбор,
  с `none` — «не найден», любой другой — один ID.
- Тяжёлые запросы (deep, маски, Telegram) «считаются» ~3 с, чтобы было видно состояние ожидания.
